Privacy policy

Last updated: September 24, 2026

This policy covers the Fierydits1 personal automation application, also referred to as FieryDits, and this public information website. The project operator can be contacted at fierydits1@gmail.com. The application is currently used for the operator's own accounts, rather than offering public registration.

Information the application accesses

  • Google account and channel information: the account identifier used by Drive, the email address used to verify an authorization when available, the authenticated YouTube channel ID, and permissions granted during Google sign-in.
  • Drive content: configured folder and file IDs, file names, file types, access permissions, selected source images, generated videos and workflow job records.
  • Publishing information: videos, titles, descriptions, captions, platform account IDs, upload or post identifiers, status messages and errors needed to carry out and track the configured workflow.
  • Authentication information: OAuth client configuration, Google access and refresh tokens, Instagram access tokens and saved X session cookies. Google passwords are entered on Google's sign-in pages, not stored as Fierydits1 credentials.

Why the information is used

The application uses this information to verify the connected account, access the operator's configured media, organize Drive folders, generate videos, publish through enabled integrations, renew authorized Google access and recover interrupted jobs. Permissions depend on the features being set up: onboarding and checks do not themselves publish posts.

The application does not sell Google user data, use it for advertising, or use it to train general-purpose AI models. Its use and transfer of data obtained through Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

Where information is stored

Depending on the operator's deployment, credentials and working files are stored on the operator's computer or supplied through deployment secret settings. Cloud runs may process data on GitHub Actions runners. Credentials can be readable by the processes running the application; access to those machines, private files and deployment settings must be restricted by the operator.

Configured Google Drive folders store source media, generated media and recovery records. Logs can contain filenames, account or job identifiers, status information, error messages and media URLs. Local configuration and recovery data remain until the operator removes them; they are not automatically erased simply because a run finishes.

Providers and public media

Google receives authorization requests and the Drive or YouTube operations required by the workflow. Fierydits1 uses YouTube API Services; Google's handling of information is described in the Google Privacy Policy.

When Instagram publishing is enabled, the generated video may be uploaded to the operator's Render-hosted media service so Meta can fetch it. That media URL is publicly accessible to anyone who has the link while the file is available. Temporary files may remain until workflow cleanup, manual deletion or hosting cleanup occurs. Do not use this publishing path for confidential media.

Enabled Instagram and X workflows send media and accompanying text to those platforms. Published content is visible according to the platform's account and post settings. GitHub and Render may process operational data when used to run the workflow. Their own privacy policies apply to their services: GitHub, Render, Meta and X.

Retention, deletion and revoking access

The operator controls stored credentials, media, logs and job records. To stop access, stop scheduled or manual runs and revoke the relevant provider connection. Google access can be revoked through Google Account connections. Instagram authorization and X sessions can be revoked through the respective account settings.

Revoking access stops future authorized access but does not itself remove copies already stored by the application or posts already published. Remove the corresponding private credential files and deployment secrets, local working files and logs, Drive recovery records, and any remaining Render media. Delete public posts or videos separately using their platform's controls. Provider backups and logs follow the provider's retention practices.

For questions or a deletion request concerning data held by the operator, email fierydits1@gmail.com, identifying the relevant account or content without sending passwords or tokens. The operator may need to verify that the request relates to your account.

This website

This static website has no sign-in, advertising, analytics scripts, tracking pixels, third-party embeds or application cookies. When hosted on GitHub Pages, GitHub logs visitors' IP addresses for security purposes. Following an external link opens another service governed by its own policy. Emailing the operator shares the information included in your message.

Changes and contact

This page will be updated if the application's data handling changes. The date above identifies the latest revision. Privacy questions can be sent to fierydits1@gmail.com.
